## 1. Feature gaps vs. the mobile app

The mobile app (`Athlete-Assessment`) and this web app share one Supabase project and largely mirror each other's screens, but the mobile `DataSource` interface (`src/data/datasource.ts`) had 21+ methods with **no equivalent anywhere in web** — neither in `datasource.ts`/`SupabaseDataSource.ts` nor called from any page. These weren't lint noise; they were whole features a coach only got on the phone, not the browser.

**Status: 1a, 1b, 1c, 1e, 1f, 1g (owner side), 1h, 1i are fixed and merged into web** (see each subsection). **1d (Stripe Connect) is deliberately held off** — it's payment/payout onboarding infrastructure and was flagged for the user to schedule separately rather than build unprompted in the same pass as everything else.

### 1a. ✅ Fixed — assessor accept/decline was two bugs deep
- Turned out worse than "missing an accept button": web's dashboard never rendered Accept/Decline UI at all, and the `rejectAssignedTryout` mutation that did exist called `.delete()` on `tryout_assessors` **as the assessor**, which the `tryout_assessors_write` RLS policy (account staff only) silently matches zero rows on — confirmed against the mobile repo's migration `20260812200000_assessor_status_rpc.sql`, which documents this exact silent no-op and introduces `set_assessor_status()`, a `SECURITY DEFINER` RPC, as the fix. On top of that, the mutation invalidated query key `['assignedTryouts', user?.id, user?.email]` while the query itself was keyed on `['tryouts', 'assigned']` (`queryKeys.assignedTryouts`), so even a successful reject wouldn't have refreshed the list.
- Fixed by switching both `acceptAssignedTryout` (new) and `rejectAssignedTryout` to call `set_assessor_status` via RPC, filtering `listAssignedTryouts` to exclude declined invites, invalidating the correct query key, and adding Accept/Decline buttons to the "Assigned to me" card on [dashboard/page.tsx](src/app/(app)/dashboard/page.tsx) (shown only while the caller's own assessor entry is `status: 'pending'`, mirroring mobile's `isPending` check). Verified with `tsc --noEmit`, `eslint`, and `next build` — all clean, no new lint findings. Not verified by clicking through an authenticated session (no test credentials available in this session).
- **Follow-up spotted, not fixed**: `listAssignedTryouts` also doesn't filter out soft-deleted tryouts (`.is('deleted_at', null)`, present in mobile's version since migration `20260810160000_soft_delete_preserves_history.sql`); web doesn't reference `deleted_at` anywhere, so it's unclear whether web's own delete/restore flow even uses that column. Needs its own investigation before touching.

## 2. ✅ Fixed — lint errors (was 62 errors, 19 warnings; now 1 error, 7 warnings)

### `no-explicit-any` — 75 fixed, 1 intentionally kept
Went from ~75 occurrences (the original estimate undercounted — a full re-scan found more) down to exactly **one**: [SupabaseDataSource.ts:71](src/data/supabase/SupabaseDataSource.ts:71), `type Row = Record<string, any>`. Kept deliberately — it's the file's one documented, contained escape hatch for loosely-shaped Supabase row/RPC-response objects. The alternative (full `unknown` cascading through hundreds of property accesses, or generating real Supabase DB types, which needs a live DB connection this environment doesn't have) would be a disproportionate rewrite for a lint pass. Every other site now uses `Row`, a real interface (`SupabaseClient`, `Tryout`, `CustomRubric`, `Season`, `SeasonEvent`, `GuardianRosterAthlete`, etc.), or `unknown` with a narrowing guard.
- Along the way: added a shared `extractFunctionErrorMessage()` helper that replaced ~9 duplicated try/catch blocks parsing a Supabase edge-function error body (`error.context.json()`), each of which had been individually casting to `any` to reach `.context`.
- Also found and fixed two methods (`createAndInviteUser`, `resendGuardianInvite`) that were implemented on `SupabaseDataSource` but missing from the `DataSource` interface — the only reason those call sites needed `(getDataSource() as any)` at all. Added both to the interface; the casts are now unnecessary and gone. This was a real gap: any other `DataSource` implementation (e.g. a test double) could have silently lacked these two methods with no type error.

### `react-hooks/set-state-in-effect` — 7 fixed (3 more than originally found)
The original scan's regex missed several; a full re-check found 7 total, all fixed:
- [hooks.ts](src/lib/hooks.ts) `useMounted()`, [Modal.tsx](src/components/ui/Modal.tsx) (now reuses `useMounted()`) — rewritten with `useSyncExternalStore` (server snapshot `false`, client snapshot `true`), the canonical hydration-mismatch-without-an-effect pattern.
- [ScorePad.tsx](src/components/ui/ScorePad.tsx), [AppShell.tsx](src/components/AppShell.tsx), [AddToRosterModal.tsx](src/components/assessment/AddToRosterModal.tsx) — "reset when a prop changes" cases, fixed via React's documented "storing information from previous renders" pattern (comparing against a `usePrev`-style state value and adjusting during render) rather than an effect. Tried the ref-based render-time variant first; this repo's React Compiler config disallows ref access during render too, so the state-comparison version is what stuck.
- [team-builder/page.tsx](src/app/(app)/assessment/[id]/team-builder/page.tsx), [player/[playerId]/page.tsx](src/app/(app)/assessment/[id]/player/[playerId]/page.tsx) — rotating loading-text effects; kept the `setInterval` as a real effect (it's a legitimate external-system subscription) but stopped resetting the displayed text synchronously at the effect's start — that value is now derived (`isPending ? TEXTS[index % TEXTS.length] : idleText`) instead of stored redundantly.
- [rinkside/page.tsx](src/app/(app)/assessment/[id]/rinkside/page.tsx) — the flagged calls (`setRecommendation('')`, `setShowRecError(false)`) were resetting state to the exact same value their own `useState` initializers already used; simply redundant, deleted rather than reworked.

### React Compiler memoization bailout — fixed
[Fields.tsx](src/components/ui/Fields.tsx) — the `useMemo` re-sorted the entire (constant) `COUNTRY_CODES` list on every keystroke, keyed on `value`, even though the sort itself never depended on `value`. Hoisted the sort to module scope (`COUNTRY_CODES_BY_LENGTH`, computed once at import time) and left only the actually-`value`-dependent `.find()` in the component — simple enough now that the compiler auto-memoizes it without a manual `useMemo`.

### `no-require-imports` — fixed
- [SupabaseDataSource.ts](src/data/supabase/SupabaseDataSource.ts) `logout()` — the `require('@/lib/storage')` call was reached via a `storage.getAllKeys()` method **that doesn't exist** on web's `storage` object (only `getString`/`set`/`remove`) — this was a real, live bug: every `logout()` call threw `TypeError: storage.getAllKeys is not a function` inside a `finally` block. Also, even a correct `getAllKeys()` would have routed removal through `storage.remove()`, which prefixes keys with `aas-web:` — but the actual target (Supabase SDK's own `sb-*` auth-token keys) was never stored under that prefix, so it would have missed them regardless. Fixed by sweeping `window.localStorage` directly instead of going through this app's own namespaced KV wrapper.
- [queryClient.ts](src/lib/queryClient.ts) — `require('../state/authStore')` was breaking a genuine circular import (authStore imports queryClient to clear the cache on logout); replaced with a dynamic `import()`, which defers resolution the same way but works under strict ESM.

### Unused vars — fixed (11 found, more than the original 7)
`_sport`/`_label` params kept for interface/signature parity got `eslint-disable-next-line` comments (renaming wouldn't have satisfied this preset's rule, which doesn't special-case `_`-prefixed names). Everything else was genuinely dead and removed: an unused `useAthleteHistoryQuery` prefetch on the score page that fired a real, purposeless network request every load; an unused `money()` formatter and `Link` import; two `catch (e) {}` blocks switched to the bare `catch {}` syntax; an unused destructured `data` from an athlete-update call.
