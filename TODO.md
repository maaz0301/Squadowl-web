## 1. Feature gaps vs. the mobile app

The mobile app (`Athlete-Assessment`) and this web app share one Supabase project and largely mirror each other's screens, but the mobile `DataSource` interface (`src/data/datasource.ts`) had 21+ methods with **no equivalent anywhere in web** — neither in `datasource.ts`/`SupabaseDataSource.ts` nor called from any page. These weren't lint noise; they were whole features a coach only got on the phone, not the browser.

**Status: all of 1a-1i are fixed and merged into web** (see each subsection). A 2026-08-21 re-sweep confirmed the `DataSource` interfaces now differ by four methods only: `addSeasonPlayers`/`listSeasonRoster` (mobile's chunked-RPC perf helpers — web does the same work sequentially, see 1i) and `getDatabase`/`saveDatabase` (dead code web deleted, see section 3). No feature method is missing, and every mobile screen has a web counterpart.

### 1a. ✅ Fixed — assessor accept/decline was two bugs deep
- Turned out worse than "missing an accept button": web's dashboard never rendered Accept/Decline UI at all, and the `rejectAssignedTryout` mutation that did exist called `.delete()` on `tryout_assessors` **as the assessor**, which the `tryout_assessors_write` RLS policy (account staff only) silently matches zero rows on — confirmed against the mobile repo's migration `20260812200000_assessor_status_rpc.sql`, which documents this exact silent no-op and introduces `set_assessor_status()`, a `SECURITY DEFINER` RPC, as the fix. On top of that, the mutation invalidated query key `['assignedTryouts', user?.id, user?.email]` while the query itself was keyed on `['tryouts', 'assigned']` (`queryKeys.assignedTryouts`), so even a successful reject wouldn't have refreshed the list.

Verified with `tsc --noEmit`, `eslint`, and `next build` — all clean, no new lint findings. Not verified by clicking through an authenticated session (no test credentials available in this session).
- **Follow-up (soft delete), now fixed**: `listAssignedTryouts`, `listTryouts`, and `getTryout` all filter `.is('deleted_at', null)` ([SupabaseDataSource.ts](src/data/supabase/SupabaseDataSource.ts)), and `deleteTryout` writes `deleted_at` rather than hard-deleting — matching mobile's soft-delete model from migration `20260810160000_soft_delete_preserves_history.sql`.

## 2. ✅ Fixed — lint errors (was 37 errors, 21 warnings as of 2026-08-20; now 0 errors, 7 warnings)

### `no-explicit-any` — 34 fixed in this pass, 1 intentionally kept
[SupabaseDataSource.ts:80](src/data/supabase/SupabaseDataSource.ts:80), `type Row = Record<string, any>`, is the one deliberately-kept exception — it's the file's documented, contained escape hatch for loosely-shaped Supabase row/RPC-response objects, now carrying its own `eslint-disable-next-line` (a plain block comment above it doesn't work — ESLint's `eslint-disable-next-line` directive only binds to the literal next line, so a two-line comment pushed the disable onto the wrong line and silently stopped suppressing anything). Every other site now uses `Row`, a real interface (`SupabaseClient`, `Tryout`, `CustomRubric`, etc.), or a narrowed type — mostly by simply *removing* redundant `as any`/`: any` annotations on values that were already implicitly `any` from an untyped Supabase call, not by adding new casts.
- Added a shared `extractFunctionErrorMessage()` helper ([SupabaseDataSource.ts](src/data/supabase/SupabaseDataSource.ts), right after `unwrap()`) that replaced 4 duplicated try/catch blocks parsing a Supabase Edge Function error body (`error.context.json()`) in `inviteTeamManager`, `createAndInviteUser`, `getAiPlayerSummary`, and `getAiCompare`.
- Removing an `any` sometimes uncovered a genuine, previously-silenced type mismatch rather than a redundant cast — e.g. `event_availability`'s `season_roster`/`athletes` joins and `season_roster`'s `seasons` join are typed as arrays by the client (to-many join shape) but were being accessed as single objects. Fixed with the same `Array.isArray(x) ? x[0] : x` unwrap already used elsewhere in this file for the same pattern, rather than re-adding a cast to paper over it.

### `react-hooks/set-state-in-effect` — 2 fixed
[DummyDataModal.tsx](src/components/DummyDataModal.tsx) and [AddToRosterModal.tsx](src/components/assessment/AddToRosterModal.tsx) each had a `useEffect` synchronously resetting a "just clicked" flag when a loading prop turned false. Both rewritten with React's "storing information from previous renders" pattern (comparing against a `prevLoading`-style state value and adjusting during render) — the same convention [ScorePad.tsx](src/components/ui/ScorePad.tsx) already uses.

### `no-require-imports` — fixed
- [SupabaseDataSource.ts](src/data/supabase/SupabaseDataSource.ts) `logout()` — `require('@/lib/storage')` routed through a `storage.getAllKeys()` method that doesn't exist on web's `storage` wrapper (only `getString`/`set`/`remove`), so every `logout()` call threw inside a `finally` block. Fixed by sweeping `window.localStorage` directly (guarded by `typeof window !== 'undefined'` for SSR safety) for the Supabase SDK's own `sb-*`/`auth-token` keys, since those were never stored under this app's own `aas-web:` namespace prefix anyway.

### React Compiler memoization bailout — fixed (still holds, from the original pass)
[Fields.tsx](src/components/ui/Fields.tsx) — the `useMemo` re-sorted the entire (constant) `COUNTRY_CODES` list on every keystroke, keyed on `value`, even though the sort itself never depended on `value`. ### Dead code and unused vars — cleaned up
`WRITABLE_ROLES` and `isStaleAccountError()` had zero callers anywhere in the file — removed rather than kept around unused. Seven `catch (_) { }` blocks (Stripe Connect status/checkout error handling) switched to bare `catch { }`, matching the convention used elsewhere. `createShareLink`'s unused `_label` param (kept for `DataSource` interface parity) got an `eslint-disable-next-line` rather than a rename, since this preset's rule doesn't special-case `_`-prefixed params. An unused destructured `data` from an `updateAthlete`-adjacent call was dropped in favor of `const { error } = ...`.
